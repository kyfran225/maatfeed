# 12. ACCESSIBILITÉ, PERFORMANCE ET QUALITÉ UX DU SYSTÈME

## 1. OBJECTIF UX

Rendre Notifications, Inbox et Activity utilisables, rapides, accessibles, calmes et fiables sur tous les appareils.

## 2. ÉMOTION RECHERCHÉE

Confiance.

L'utilisateur doit sentir que rien ne lui échappe, mais que rien ne l'agresse.

## 3. STRUCTURE VISUELLE GLOBALE

Qualité attendue :

- lisibilité
- contrastes
- états clairs
- navigation clavier
- lecteur d'écran
- contrôle utilisateur
- performance
- cache
- faible connexion
- sobriété

## 4. LAYOUT EXACT

Tous les écrans doivent accepter :

- texte long
- groupes nombreux
- zéro notification
- mauvaise connexion
- mini-player audio actif
- safe areas
- clavier
- zoom système

## 5. HIERARCHIE VISUELLE

La priorité UX doit dominer :

1. action requise
2. direct
3. suivi
4. recommandation
5. historique

## 6. POSITIONNEMENT DES ÉLÉMENTS

Les éléments critiques doivent rester faciles à atteindre.

### Sur mobile :

- actions fréquentes proches du pouce
- menu préférences accessible
- pas de bouton important caché trop loin

## 7. DIMENSIONS & ESPACEMENTS

Respecter :

- touch target 44 px
- cartes aérées
- texte non minuscule
- gaps réguliers
- safe area bas avec mini-player

## 8. COULEURS

Contraste fort.

- non-lu visible sans couleur seule
- priorité visible par icône + texte
- focus ambre net
- erreurs lisibles sans rouge violent

## 9. TYPOGRAPHIE

- titres courts
- descriptions courtes
- line-height confortable
- pas de jargon technique
- temps relatif clair

## 10. BOUTONS

Boutons :

- labels explicites
- états loading
- disabled expliqué
- undo pour actions rapides
- confirmation pour suppression massive

## 11. CARTES

Cartes :

- type clair
- état clair
- action claire
- contexte visible
- fallback si objet supprimé

## 12. ICONOGRAPHIE

Icônes jamais seules pour information critique.

Toujours combiner avec texte pour priorité, sécurité, paiement ou modération.

## 13. COMPORTEMENT SCROLL

- préserver position
- éviter jumps
- sticky modéré
- pagination progressive
- retour haut optionnel

## 14. ANIMATIONS

- sobres
- rapides
- réduisibles
- jamais essentielles

## 15. MICRO INTERACTIONS

Feedbacks :

- lu/non-lu
- action en attente
- archive
- synchronisation
- erreur
- préférence changée

## 16. GESTURES MOBILE

Gestures utiles mais non obligatoires.

Alternative visible pour tout.

## 17. ÉTATS LOADING

Skeletons réalistes.

Pas de faux contenu.

Pas de spinner central isolé.

## 18. ÉTATS ERREUR

Messages humains.

Actions utiles.

Conserver contenu cache.

## 19. ÉTATS OFFLINE

Actions offline en file.

Statut visible.

Synchronisation claire.

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

### Mobile :

- priorité aux actions simples

### Tablet :

- aperçu possible

### Desktop :

- efficacité, preview, clavier

## 21. ACCESSIBILITÉ

Obligatoire :

- aria-labels conceptuels côté implémentation
- lecteur d'écran
- navigation clavier
- focus visible
- contraste
- réduction motion
- textes alternatifs
- état lu/non-lu explicite

## 22. PERFORMANCE UX

- compteur rapide
- cache liste
- groupement
- pagination
- lazy-load
- pas d'images lourdes
- sync différée
- mise à jour optimiste contrôlée

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

Le système doit être conçu pour :

- réseau irrégulier
- usage mobile
- data limitée
- interruptions
- offline fréquent
- téléphones modestes

## 24. RÈGLES NON NÉGOCIABLES

- Ne pas fatiguer l'utilisateur
- Ne pas gonfler artificiellement les badges
- Ne pas bloquer l'écran
- Ne pas cacher les priorités
- Ne pas ignorer offline
- Ne pas utiliser d'animations nerveuses
- Ne pas perdre les actions utilisateur
