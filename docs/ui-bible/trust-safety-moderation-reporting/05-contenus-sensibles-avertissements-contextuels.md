# 5. CONTENUS SENSIBLES ET AVERTISSEMENTS CONTEXTUELS

## 1. OBJECTIF UX

Gérer les contenus sensibles avec prudence, respect et contextualisation, sans infantiliser l'utilisateur ni masquer automatiquement les sujets importants.

## 2. ÉMOTION RECHERCHÉE

Prudence respectueuse.
L'utilisateur doit être prévenu, pas repoussé brutalement.

## 3. STRUCTURE VISUELLE GLOBALE

Contenus sensibles possibles :

- violence historique ;
- persécution ;
- esclavage ;
- colonisation ;
- conflits religieux ;
- discrimination ;
- contenus choquants ;
- récits traumatiques ;
- débats spirituels sensibles ;
- accusation forte ;
- documents controversés.

Avertissements :

- contexte ;
- raison ;
- choix utilisateur ;
- lien règles ;
- possibilité continuer.

## 4. LAYOUT EXACT

Dans le feed :

- carte légèrement floutée ou masquée ;
- badge "Sujet sensible" ;
- bouton "Voir avec contexte".

Dans le débat :

- bandeau contextuel sous le header ;
- pas de masquage excessif des discussions légitimes.

Dans média :

- overlay avant lecture ;
- contrôle utilisateur.

## 5. HIERARCHIE VISUELLE

- type de sensibilité ;
- raison ;
- choix ;
- action.

Ne pas afficher un avertissement vague qui fait peur.

## 6. POSITIONNEMENT DES ÉLÉMENTS

Avertissement :

- au-dessus du contenu ;
- ou sur le média avant lecture ;
- jamais loin dans un menu.

## 7. DIMENSIONS & ESPACEMENTS

Carte avertissement :

- 96 à 160 px ;
- padding 16 px ;
- bouton 44 à 52 px ;
- badge 24 à 28 px.

Overlay média :

- couvre média ;
- texte centré ;
- bouton bas.

## 8. COULEURS

Sensible :

- fond graphite ;
- bordure ocre ;
- badge ocre doux ;
- texte beige ;
- bouton ambre sombre.

## 9. TYPOGRAPHIE

Message :

- direct ;
- court ;
- sans sensationnaliser.

Exemple :
"Ce contenu aborde un sujet historique violent. Tu peux continuer avec le contexte."

## 10. BOUTONS

Actions :

- Voir le contenu ;
- Voir avec contexte ;
- Masquer ;
- Pourquoi cet avertissement ;
- Signaler ;
- Gérer préférences.

## 11. CARTES

Carte sensible :

- badge ;
- raison ;
- action ;
- option contexte ;
- option masquer.

## 12. ICONOGRAPHIE

- alerte ocre ;
- bouclier ;
- contexte ;
- œil ;
- œil masqué ;
- info.

## 13. COMPORTEMENT SCROLL

Le contenu sensible masqué doit occuper un espace compact.
Ne pas créer de grands blocs qui cassent le feed.

## 14. ANIMATIONS

- reveal doux ;
- flou qui disparaît progressivement ;
- pas de choc visuel ;
- pas d'effet dramatique.

## 15. MICRO INTERACTIONS

- tap "pourquoi" ;
- tap "voir" ;
- tap "masquer" ;
- préférence mémorisée si utilisateur le choisit.

## 16. GESTURES MOBILE

- tap ;
- long press options ;
- swipe masquer ;
- pas de reveal par geste accidentel.

## 17. ÉTATS LOADING

Si contexte charge :

- afficher avertissement ;
- bouton désactivé brièvement ;
- pas de contenu brut sans contexte si sensibilité élevée.

## 18. ÉTATS ERREUR

Si contexte indisponible :

- proposer voir quand même si autorisé ;
- ou masquer si contenu critique ;
- message clair.

## 19. ÉTATS OFFLINE

Offline :

- appliquer règles cache ;
- afficher avertissements locaux ;
- contexte complet peut être indisponible.

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

Mobile :

- carte compacte.

Desktop :

- panneau contexte possible.

Tablet :

- overlay + détail.

## 21. ACCESSIBILITÉ

- avertissement annoncé ;
- bouton clair ;
- pas de flou comme seule information ;
- lecteur d'écran doit comprendre le type de contenu.

## 22. PERFORMANCE UX

- avertissements locaux ;
- pas d'images lourdes ;
- contexte textuel léger ;
- préférences cache.

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

- avertissement texte ;
- contexte court ;
- média non préchargé ;
- choix utilisateur conservé.

## 24. RÈGLES NON NÉGOCIABLES

- Prévenir sans sensationnaliser.
- Respecter les sujets historiques.
- Ne pas masquer les débats légitimes sans raison.
- Donner un choix.
- Expliquer.
- Pas de reveal accidentel.
- Préférences utilisateur respectées.
