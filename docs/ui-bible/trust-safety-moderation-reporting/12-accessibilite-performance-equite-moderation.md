# 12. ACCESSIBILITÉ, PERFORMANCE ET ÉQUITÉ DE LA MODÉRATION

## 1. OBJECTIF UX

Garantir que le système Trust & Safety soit accessible, rapide, équitable, compréhensible et non discriminatoire dans son expérience utilisateur.

## 2. ÉMOTION RECHERCHÉE

Justice.
L'utilisateur doit sentir que les règles sont appliquées avec cohérence.

## 3. STRUCTURE VISUELLE GLOBALE

Qualité attendue :

- langage clair ;
- décisions explicables ;
- actions réversibles quand possible ;
- recours ;
- accessibilité ;
- performance ;
- faible connexion ;
- respect culturel ;
- respect religieux ;
- prudence sur sujets sensibles.

## 4. LAYOUT EXACT

Toutes les interfaces de sécurité doivent contenir :

- titre clair ;
- raison ;
- action ;
- détails ;
- recours si applicable.

## 5. HIERARCHIE VISUELLE

La raison doit toujours être visible avant la sanction forte.
Le recours doit être visible pour les décisions importantes.

## 6. POSITIONNEMENT DES ÉLÉMENTS

Les informations essentielles doivent être près de la décision :

- contenu concerné ;
- règle liée ;
- action appliquée ;
- bouton révision.

## 7. DIMENSIONS & ESPACEMENTS

Messages de décision :

- 100 à 180 px ;
- détails repliables ;
- CTA 44 à 52 px ;
- texte lisible.

## 8. COULEURS

Équité :

- or/beige pour information ;
- ocre pour prudence ;
- rouge sombre rare ;
- fond sobre.

## 9. TYPOGRAPHIE

Pas de termes juridiques lourds dans l'UI principale.
Utiliser :

- "Ce contenu a été masqué"
- "Cette réponse demande une source"
- "Tu peux demander une révision"

## 10. BOUTONS

Actions :

- Demander révision ;
- Voir règle ;
- Modifier ;
- Supprimer ;
- Contacter support ;
- Retour.

## 11. CARTES

Carte décision :

- action ;
- règle ;
- contenu ;
- date ;
- recours ;
- statut.

## 12. ICONOGRAPHIE

- balance ;
- bouclier ;
- règle ;
- révision ;
- info.

## 13. COMPORTEMENT SCROLL

Les détails longs sont repliés.
La décision principale reste visible.

## 14. ANIMATIONS

Sobres.
Aucune animation de sanction spectaculaire.

## 15. MICRO INTERACTIONS

- tap règle ;
- tap recours ;
- copier référence ;
- voir contenu concerné si autorisé.

## 16. GESTURES MOBILE

- tap ;
- pas de swipe pour recours critique ;
- confirmation actions.

## 17. ÉTATS LOADING

Révision envoyée :

- statut clair ;
- pas de promesse excessive.

## 18. ÉTATS ERREUR

Si recours échoue :

- conserver texte ;
- retry ;
- message clair.

## 19. ÉTATS OFFLINE

Recours peut être préparé offline mais envoyé en ligne.

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

Mobile :

- simple.

Desktop :

- historique plus détaillé.

## 21. ACCESSIBILITÉ

- décisions annoncées ;
- raison textuelle ;
- recours accessible ;
- contraste ;
- focus.

## 22. PERFORMANCE UX

- décisions cache ;
- pas de médias lourds ;
- actions légères.

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

- décisions visibles en cache ;
- recours en attente ;
- messages courts.

## 24. RÈGLES NON NÉGOCIABLES

- Modération expliquée.
- Recours visible pour décisions importantes.
- Pas d'arbitraire opaque.
- Respect culturel.
- Respect religieux.
- Accessibilité totale.
- Performance légère.
