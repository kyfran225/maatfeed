# 7. APPELS À LA NUANCE ET UX ANTI-TOXICITÉ

## 1. OBJECTIF UX

Encourager des réponses plus constructives avant que le débat ne se dégrade. L'objectif n'est pas de rendre tout doux, mais de garder l'intelligence du désaccord.

## 2. ÉMOTION RECHERCHÉE

Respiration.
L'utilisateur doit sentir une invitation à mieux formuler, pas une punition.

## 3. STRUCTURE VISUELLE GLOBALE

Moments d'intervention :

- avant publication ;
- après détection d'un ton agressif ;
- quand un débat devient très tendu ;
- quand plusieurs signalements arrivent ;
- quand une réponse manque de source ;
- quand un utilisateur écrit en majuscules/agressif ;
- quand un fil tourne en répétition.

## 4. LAYOUT EXACT

Dans composer :

- petite carte sous le texte ;
- suggestion de reformulation ;
- bouton "rendre plus nuancé".

Dans débat :

- bandeau court "Le débat devient intense" ;
- rappel des règles ;
- accès au résumé.

## 5. HIERARCHIE VISUELLE

- alerte douce ;
- raison ;
- action constructive ;
- option ignorer si autorisé.

## 6. POSITIONNEMENT DES ÉLÉMENTS

Toujours proche de l'action :

- sous composer ;
- dans thread près du fil concerné ;
- jamais en pop-up globale sauf crise.

## 7. DIMENSIONS & ESPACEMENTS

Carte nuance :

- 64 à 110 px ;
- padding 12 à 16 px ;
- bouton 36 à 44 px ;
- radius 18 à 22 px.

## 8. COULEURS

Nuance :

- ambre doux ;
- fond graphite ;
- bordure or faible ;
- pas de rouge.

## 9. TYPOGRAPHIE

Messages :

- "Cette réponse gagnerait en nuance."
- "Tu peux viser l'idée plutôt que la personne."
- "Une source rendrait ton argument plus solide."

Ton calme, jamais moralisateur.

## 10. BOUTONS

Actions :

- Reformuler ;
- Ajouter nuance ;
- Ajouter source ;
- Publier quand même ;
- Voir règle ;
- Annuler.

## 11. CARTES

Carte reformulation :

- phrase originale ;
- suggestion ;
- bouton remplacer ;
- bouton copier ;
- bouton ignorer.

## 12. ICONOGRAPHIE

- plume ;
- balance ;
- cercle ;
- source ;
- lumière douce.

## 13. COMPORTEMENT SCROLL

L'alerte doit rester attachée au composer.
Si l'utilisateur scrolle, ne pas persister partout.

## 14. ANIMATIONS

- apparition douce ;
- highlight phrase concernée ;
- remplacement avec flash or léger.

## 15. MICRO INTERACTIONS

- tap reformuler ;
- tap ajouter source ;
- tap ignorer ;
- feedback utile/pas utile.

## 16. GESTURES MOBILE

- tap ;
- swipe down détails ;
- long press suggestion.

## 17. ÉTATS LOADING

Reformulation :

- skeleton court ;
- composer reste actif ;
- pas de blocage.

## 18. ÉTATS ERREUR

Si reformulation échoue :

- garder texte ;
- proposer continuer sans IA.

## 19. ÉTATS OFFLINE

Offline :

- messages de règles locaux ;
- reformulation IA indisponible ;
- brouillon conservé.

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

Mobile :

- carte inline.

Tablet/Desktop :

- panneau suggestion.

## 21. ACCESSIBILITÉ

- alerte annoncée ;
- suggestions lisibles ;
- remplacement contrôlé ;
- focus conservé.

## 22. PERFORMANCE UX

- pas d'analyse permanente ;
- déclencher au moment publier ou pause ;
- suggestions courtes.

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

- règles locales ;
- IA optionnelle ;
- pas de blocage ;
- brouillon sauvegardé.

## 24. RÈGLES NON NÉGOCIABLES

- Encourager sans infantiliser.
- Ne pas punir un désaccord fort.
- Viser la forme problématique.
- L'utilisateur garde contrôle.
- Aucune reformulation automatique publiée.
- Le débat reste vivant.
