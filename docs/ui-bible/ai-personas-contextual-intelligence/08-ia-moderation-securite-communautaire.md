# 8. IA, MODÉRATION ET SÉCURITÉ COMMUNAUTAIRE

## 1. OBJECTIF UX

Utiliser l'IA pour assister la modération, réduire la toxicité, encourager la nuance et signaler les risques, sans créer une police invisible ou arbitraire.

## 2. ÉMOTION RECHERCHÉE

Sécurité sans étouffement.

L'utilisateur doit sentir que le débat est protégé, pas contrôlé brutalement.

## 3. STRUCTURE VISUELLE GLOBALE

L'IA peut intervenir pour :

- détecter ton agressif
- proposer reformulation
- signaler manque de sources
- repérer attaques personnelles
- alerter sur sujet sensible
- aider modérateurs humains
- contextualiser une décision
- ralentir une réponse impulsive

## 4. LAYOUT EXACT

### Avant publication :

- suggestion douce dans composer
- bouton "Reformuler avec plus de nuance"
- l'utilisateur peut ignorer selon gravité

### Après publication :

- badge modération si nécessaire
- action signaler
- message contextuel

### Côté modération :

- panneau d'analyse
- score non visible publiquement
- recommandations, pas décision finale automatique pour cas sensibles

## 5. HIERARCHIE VISUELLE

Priorité :

1. sécurité
2. respect
3. liberté d'expression
4. nuance
5. pédagogie

## 6. POSITIONNEMENT DES ÉLÉMENTS

### Alerte pré-publication :

- sous le champ de réponse
- non intrusive
- visible avant bouton publier

### Alerte publique :

- sous contenu concerné
- jamais humiliante

## 7. DIMENSIONS & ESPACEMENTS

### Alerte douce :

- hauteur : 52 à 90 px
- radius : 18 à 22 px
- padding : 12 à 16 px

### Panneau modération :

- mobile sheet
- desktop panneau latéral

## 8. COULEURS

### Modération :

- ocre/cuivre
- pas rouge sauf danger élevé
- fond sombre
- texte clair
- badge bouclier

## 9. TYPOGRAPHIE

Messages :

- courts
- non accusateurs
- orientés action

Exemple :

"Cette réponse peut être perçue comme une attaque personnelle. Tu peux la reformuler avant publication."

## 10. BOUTONS

Actions :

- Reformuler
- Publier quand même si autorisé
- Modifier
- Annuler
- Voir règle
- Signaler
- Demander révision

## 11. CARTES

### Carte modération IA :

- problème détecté
- raison
- suggestion
- règle liée
- action

## 12. ICONOGRAPHIE

- bouclier
- balance
- plume
- attention ocre
- règle
- signalement

## 13. COMPORTEMENT SCROLL

En cas d'alerte, ne pas scroller brutalement.

Mettre en évidence la zone concernée.

## 14. ANIMATIONS

- alerte apparaît doucement
- champ concerné halo ocre
- reformulation insérée avec highlight
- aucune animation punitive

## 15. MICRO INTERACTIONS

- tap règle : détail
- tap reformuler : suggestion
- tap ignorer : confirmation si nécessaire
- signalement : feedback clair

## 16. GESTURES MOBILE

- swipe down fermer détail
- tap modifier
- long press signalement sur contenu

## 17. ÉTATS LOADING

Analyse modération :

- très courte
- ne doit pas ralentir la publication trop longtemps
- si réseau faible, appliquer règles locales minimales

## 18. ÉTATS ERREUR

Si analyse IA indisponible :

- ne pas bloquer sauf règles critiques locales
- message discret côté système si nécessaire

## 19. ÉTATS OFFLINE

Offline :

- règles locales simples
- publication en attente
- analyse complète au retour réseau
- l'utilisateur est informé

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

### Mobile :

- alerte inline

### Tablet :

- alerte + sheet

### Desktop :

- panneau modération latéral

## 21. ACCESSIBILITÉ

- alerte annoncée
- couleur non seule
- texte clair
- boutons accessibles
- focus sur action utile

## 22. PERFORMANCE UX

- analyse légère
- règles locales
- pas de latence excessive
- pas d'appel IA pour chaque micro-frappe

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

- modération locale minimale
- file de publication
- analyse différée
- messages courts
- pas de blocage réseau permanent

## 24. RÈGLES NON NÉGOCIABLES

- L'IA assiste, elle ne doit pas être une autorité opaque
- Les cas sensibles doivent pouvoir être revus
- Les alertes doivent être respectueuses
- Pas d'humiliation publique
- Pas de censure invisible sans explication
- La sécurité communautaire prime sur le buzz
