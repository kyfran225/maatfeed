# 12. ACCESSIBILITÉ AUDIO, PERFORMANCE ET QUALITÉ D'EXPÉRIENCE

## 1. OBJECTIF UX

Garantir que l'audio soit utilisable par tous, rapide, fiable et confortable.

## 2. ÉMOTION RECHERCHÉE

L'utilisateur doit sentir une application solide, respectueuse, pensée pour lui.

## 3. STRUCTURE VISUELLE GLOBALE

### Accessibilité :
- transcriptions
- labels
- focus
- contrôles larges
- contraste
- réduction mouvement

### Performance :
- lazy loading
- cache
- qualité adaptative
- offline

## 4. LAYOUT EXACT

- contrôles toujours visibles
- transcription proche du player
- paramètres audio accessibles
- mode léger accessible sans fouiller

## 5. HIERARCHIE VISUELLE

Priorité :

1. lire/pause
2. comprendre
3. naviguer
4. sauvegarder
5. personnaliser

## 6. POSITIONNEMENT DES ÉLÉMENTS

- transcription dans full-player
- vitesse/timer près contrôles
- mode léger dans paramètres et player
- téléchargement visible

## 7. DIMENSIONS & ESPACEMENTS

- boutons minimum 44 px
- texte minimum 12 px pour meta
- transcription line-height généreux
- focus ring visible

## 8. COULEURS

- contraste élevé
- pas uniquement ambre pour information
- états accessibles aussi par texte/icône

## 9. TYPOGRAPHIE

- transcription lisible
- durée claire
- pas de texte trop fin
- pas d'uppercase excessive

## 10. BOUTONS

Tous les boutons doivent avoir :

- label
- état
- feedback
- zone tactile suffisante

## 11. CARTES

Les cartes doivent rester lisibles sans images.

## 12. ICONOGRAPHIE

Icônes accompagnées de labels quand l'action n'est pas évidente.

## 13. COMPORTEMENT SCROLL

Pas de perte de contexte.

Le player doit rester accessible sans remonter toute la page.

## 14. ANIMATIONS

Respecter réduction des animations.

Aucune animation essentielle à la compréhension.

## 15. MICRO INTERACTIONS

Feedback tactile/visuel clair, jamais dépendant d'un seul sens.

## 16. GESTURES MOBILE

Toutes les gestures doivent avoir une alternative visible.

## 17. ÉTATS LOADING

Chargement progressif, non bloquant.

## 18. ÉTATS ERREUR

Messages humains, courts, réparables.

## 19. ÉTATS OFFLINE

Offline doit être un mode complet, pas une page morte.

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

Accessibilité constante sur tous formats.

## 21. ACCESSIBILITÉ

Règles :

- transcription
- labels
- focus
- clavier
- lecteur d'écran
- contraste
- tailles tactiles
- réduction animations
- alternatives aux gestures

## 22. PERFORMANCE UX

Règles :

- audio prioritaire
- images secondaires
- cache
- lazy
- pas de re-render excessif
- queue optimisée
- waveform légère

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

Le système doit être conçu autour de cette réalité :

- audio compressé
- mode léger
- offline
- reprise
- messages simples
- pas de dépendance vidéo

## 24. RÈGLES NON NÉGOCIABLES

- Pas d'audio inaccessible
- Pas de player sans transcription possible quand disponible
- Pas de bouton minuscule
- Pas d'animation obligatoire
- Pas de dépendance à une connexion parfaite
- Pas de perte de progression
