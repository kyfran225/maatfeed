# 1. VISION GLOBALE DE L'ONBOARDING MAATFEED

## 1. OBJECTIF UX

Permettre à un nouvel utilisateur de comprendre rapidement ce qu'est MAATFEED, de choisir une première orientation personnelle et d'accéder vite à un feed pertinent.

L'onboarding doit répondre à quatre questions silencieuses :

- "Qu'est-ce que cette application m'apporte ?"
- "Est-ce que je vais m'y retrouver ?"
- "Est-ce que c'est pour moi ?"
- "Que dois-je faire maintenant ?"

Il doit introduire les grands piliers :

- savoir africain
- débats intelligents
- audio
- vidéos
- séries
- créateurs
- IA contextuelle
- personnalisation
- exploration culturelle

## 2. ÉMOTION RECHERCHÉE

L'utilisateur doit ressentir :

- curiosité
- accueil
- élégance
- confiance
- profondeur
- liberté
- appartenance
- envie d'explorer

L'onboarding doit être une porte dorée dans une bibliothèque nocturne, pas un guichet d'inscription avec néon fatigué.

## 3. STRUCTURE VISUELLE GLOBALE

L'onboarding est composé de plusieurs couches :

- écran d'accueil émotionnel
- explication courte de la proposition de valeur
- choix d'intérêts
- choix avatar symbolique
- choix archétype ou profil de découverte
- préférences de formats
- préférences de notifications légères
- mode faible connexion
- premier feed personnalisé
- onboarding progressif après usage

L'onboarding initial doit rester court. Les détails peuvent être demandés plus tard, au bon moment.

## 4. LAYOUT EXACT

### Mobile :

- expérience plein écran
- fond noir charbon
- contenu centré verticalement mais avec respiration
- progression discrète
- bouton principal en bas
- bouton "Passer" disponible selon étape
- navigation par swipe possible
- aucune surcharge textuelle

### Desktop :

- onboarding en panneau central
- illustration ou symbole à gauche
- choix et actions à droite
- largeur maximale 880 à 1040 px
- fond immersif plein écran
- pas de page blanche

## 5. HIERARCHIE VISUELLE

Hiérarchie générale :

1. message principal
2. bénéfice utilisateur
3. action principale
4. choix secondaires
5. détails facultatifs

Le bouton principal doit toujours être évident.
Le texte doit rester court.
Les choix doivent être visuels et scannables.

## 6. POSITIONNEMENT DES ÉLÉMENTS

### Sur mobile :

- symbole ou animation légère en haut
- titre au centre supérieur
- texte court sous le titre
- choix au centre
- boutons en bas
- progression discrète en haut ou bas

### Sur desktop :

- gauche : univers visuel MAATFEED
- droite : étape active
- bas : actions

## 7. DIMENSIONS & ESPACEMENTS

### Mobile :

- padding horizontal : 20 px
- espace entre titre et texte : 10 à 14 px
- espace entre texte et choix : 24 à 32 px
- bouton principal : 52 à 56 px de haut
- radius bouton : 22 à 28 px
- cartes choix : 88 à 140 px selon étape
- gap entre cartes : 10 à 14 px

### Desktop :

- carte onboarding : 720 à 1040 px large
- padding : 32 à 48 px
- bouton : 52 à 60 px
- grille choix : 2 à 3 colonnes

## 8. COULEURS

Palette :

- fond : noir charbon profond
- surfaces : graphite chaud
- accents : ambre/or
- texte principal : blanc chaud
- texte secondaire : beige grisé
- progression : ambre doux
- sélection : bordure or + halo subtil
- désactivé : brun/gris chaud

Aucun fond blanc massif.
Aucun bleu SaaS.
Aucune couleur enfantine.

## 9. TYPOGRAPHIE

### Mobile :

- titre : 24 à 30 px
- sous-texte : 14 à 16 px
- cartes : 14 à 16 px
- détails : 12 à 13 px
- bouton : 15 à 16 px

### Desktop :

- titre : 34 à 44 px
- sous-texte : 16 à 18 px
- cartes : 15 à 17 px

Ton éditorial :

- court
- humain
- culturel
- direct
- jamais professoral

## 10. BOUTONS

Boutons principaux :

- Commencer
- Continuer
- Choisir
- Voir mon feed
- Personnaliser
- Passer pour l'instant
- Activer mode léger
- Reprendre plus tard

Le bouton "Passer" doit être visible mais secondaire.
MAATFEED ne doit pas enfermer l'utilisateur dans l'onboarding.

## 11. CARTES

Les cartes d'onboarding doivent être tactiles, lisibles et symboliques.

Types :

- carte intérêt
- carte avatar
- carte archétype
- carte format préféré
- carte mode réseau
- carte créateur
- carte débat
- carte audio

Chaque carte doit avoir :

- symbole
- titre
- phrase courte
- état sélectionné
- feedback

## 12. ICONOGRAPHIE

Iconographie :

- boussole
- papyrus
- onde audio
- cercle de débat
- constellation
- sceau
- plume
- flamme calme
- masque abstrait non humain
- livre symbolique
- route/chemin

Les icônes doivent rester fines, premium, sobres.

## 13. COMPORTEMENT SCROLL

L'onboarding initial doit éviter le scroll long.

Si une étape contient beaucoup de choix :

- utiliser grille courte
- afficher 6 à 9 choix maximum
- bouton "voir plus"
- scroll interne contrôlé

Sur mobile, éviter que le clavier ou la bottom safe area cache les actions.

## 14. ANIMATIONS

Animations :

- apparition douce des étapes
- transition latérale légère
- sélection carte avec halo ambre
- progression qui avance calmement
- symbole qui respire très légèrement
- fin d'onboarding avec transition vers feed

Aucune animation longue.
Aucun effet gadget.

## 15. MICRO INTERACTIONS

- tap carte : sélection immédiate
- multi-sélection : compteur discret
- bouton continuer devient actif
- choix avatar : halo autour du symbole
- choix archétype : résumé personnalisé
- choix format : aperçu mini
- "Passer" : transition douce, pas culpabilisante

## 16. GESTURES MOBILE

Gestes :

- swipe pour passer écran introductif
- tap pour sélectionner
- long press pour voir description avatar
- swipe horizontal entre avatars
- swipe down pour fermer détail
- retour système respecté

Chaque geste doit avoir une alternative visible.

## 17. ÉTATS LOADING

### Loading initial :

- logo ou symbole MAATFEED
- skeleton léger
- texte court
- pas de spinner isolé

### Loading personnalisation :

- "Préparation de ton premier feed…"
- cartes skeleton
- affichage progressif

## 18. ÉTATS ERREUR

Erreurs :

- impossible de sauvegarder préférences
- réseau instable
- création feed échouée
- avatar non chargé

Réponse UX :

- conserver les choix
- proposer réessayer
- proposer continuer sans personnalisation
- sauvegarder plus tard

## 19. ÉTATS OFFLINE

Offline :

- onboarding possible en mode limité
- choix sauvegardés localement
- feed initial basé sur contenus préchargés ou thèmes populaires
- synchronisation au retour réseau

Message :

"Tu peux commencer maintenant. Tes choix seront synchronisés quand la connexion reviendra."

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

### Mobile :

- plein écran
- peu de texte
- gros choix tactiles

### Tablet :

- cartes plus larges
- deux colonnes

### Desktop :

- expérience immersive centrée
- visuel + choix
- pas de formulaire plat

## 21. ACCESSIBILITÉ

Obligatoire :

- contraste fort
- boutons 44 px minimum
- labels textuels
- focus visible
- lecteur d'écran
- progression annoncée
- possibilité de passer
- réduction motion
- aucun sens uniquement par couleur

## 22. PERFORMANCE UX

- charger l'onboarding vite
- assets symboliques légers
- pas de vidéo obligatoire
- pas d'image lourde avant premier feed
- sauvegarde locale
- première personnalisation rapide
- lazy-load des détails

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

Priorités :

- onboarding utilisable sans réseau stable
- mode léger proposé tôt
- pas d'autoplay vidéo
- images compressées
- choix sauvegardés localement
- feed initial simple
- audio basse qualité possible
- reprise après interruption

## 24. RÈGLES NON NÉGOCIABLES

- Onboarding court au départ
- Pas de formulaire froid
- Pas de questionnaire interminable
- Pas de blocage obligatoire
- L'utilisateur peut passer
- Le mode faible connexion doit être proposé
- Les choix doivent améliorer le feed
- L'identité noir/or doit rester forte
- L'expérience doit être culturelle, premium et accueillante
