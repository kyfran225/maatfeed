# 4. CHOIX D'AVATAR SYMBOLIQUE UTILISATEUR

## 1. OBJECTIF UX

Permettre à l'utilisateur de choisir un avatar qui représente sa sensibilité, son rapport au savoir et son style d'exploration, sans utiliser de visage humain obligatoire.

Pour MAATFEED, les avatars doivent porter une identité symbolique forte, respectueuse et mémorable.

## 2. ÉMOTION RECHERCHÉE

L'utilisateur doit ressentir :

- identification
- fierté
- jeu subtil
- personnalisation
- appartenance

Il ne doit pas sentir qu'il choisit une photo de profil banale.

## 3. STRUCTURE VISUELLE GLOBALE

Écran :

- titre
- phrase courte
- grille ou carousel d'avatars
- aperçu avatar sélectionné
- signification courte
- bouton continuer
- option choisir plus tard

Les avatars doivent être non obligatoires au premier passage si l'utilisateur veut aller vite.

## 4. LAYOUT EXACT

### Mobile :

- avatar sélectionné en grand au-dessus
- carousel horizontal ou grille 2 colonnes
- description sous l'avatar actif
- bouton bas

### Desktop :

- grille avatars à gauche
- aperçu détaillé à droite

## 5. HIERARCHIE VISUELLE

1. avatar actif
2. nom
3. signification
4. choix alternatifs
5. action

L'avatar sélectionné doit être immédiatement visible.

## 6. POSITIONNEMENT DES ÉLÉMENTS

Aperçu en haut.

Choix au centre.

Boutons en bas.

Sur desktop, aperçu à droite pour donner une sensation premium.

## 7. DIMENSIONS & ESPACEMENTS

### Mobile :

- avatar aperçu : 96 à 128 px
- avatar grille : 64 à 80 px
- carte avatar : 96 à 130 px
- gap : 12 px
- radius carte : 24 px

### Desktop :

- avatar aperçu : 140 à 180 px
- grille : 4 colonnes possibles

## 8. COULEURS

Base :

- fond noir
- cartes graphite
- avatar avec fond sombre uniforme
- symbole or/cuivre/beige
- sélection : bordure ambre + halo

Chaque avatar peut avoir une nuance mais doit rester dans la palette MAATFEED.

## 9. TYPOGRAPHIE

- nom avatar : 15 à 17 px
- signification : 13 à 14 px
- détails : 12 px

## 10. BOUTONS

Boutons :

- Choisir cet avatar
- Continuer
- Changer
- Choisir plus tard
- Voir signification

## 11. CARTES

Carte avatar :

- symbole
- nom
- micro-description
- état sélectionné

Exemples d'avatars symboliques possibles :

- Le Scribe
- La Boussole
- Le Gardien des Sources
- La Voix
- Le Débatteur
- L'Éclaireur
- La Mémoire
- Le Voyageur
- La Flamme
- Le Cercle

Les noms doivent être nobles, simples, non enfantins.

## 12. ICONOGRAPHIE

Symboles :

- plume
- papyrus
- boussole
- onde
- cercle
- flamme
- étoile
- masque abstrait
- porte
- livre

Aucun portrait humain obligatoire.
Aucun visage réaliste.

## 13. COMPORTEMENT SCROLL

### Mobile :

- carousel recommandé pour aperçu émotionnel
- grille possible pour comparaison rapide

La position doit rester stable après sélection.

## 14. ANIMATIONS

- avatar sélectionné s'agrandit doucement
- halo subtil
- changement description fade
- aucune animation cartoon

## 15. MICRO INTERACTIONS

- tap avatar : sélection
- long press : signification complète
- changement avatar : preview immédiate
- bouton choisir : confirmation douce

## 16. GESTURES MOBILE

- swipe avatars
- tap sélection
- long press détails
- swipe down détail

## 17. ÉTATS LOADING

Avatars doivent être locaux.

Si assets non prêts :

- afficher symbole générique
- ne pas bloquer

## 18. ÉTATS ERREUR

Si avatar indisponible :

- remplacer par avatar symbolique par défaut
- permettre continuer

## 19. ÉTATS OFFLINE

Choix avatar entièrement disponible offline.

Synchronisation plus tard.

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

### Mobile :

- preview + carousel

### Tablet :

- grille + aperçu

### Desktop :

- galerie + fiche détaillée

## 21. ACCESSIBILITÉ

- nom textuel
- signification textuelle
- état sélectionné annoncé
- navigation clavier
- contraste
- pas de symbole seul

## 22. PERFORMANCE UX

- assets légers
- cache local
- pas d'images lourdes
- pas d'animation coûteuse

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

- avatars embarqués
- pas de téléchargement distant
- rendu immédiat
- continuer sans avatar possible

## 24. RÈGLES NON NÉGOCIABLES

- Aucun avatar humain obligatoire
- Aucun visage réaliste imposé
- Choix possible plus tard
- Avatar doit avoir un sens
- Avatar doit influencer légèrement l'expérience si pertinent
- L'utilisateur garde contrôle
