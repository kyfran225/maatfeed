# 11. CHECKLIST AGENT CODEUR - PHASE UI 13

L'agent codeur doit vérifier que la Phase UI 13 respecte les points suivants :

## SYSTÈME PWA MOBILE-FIRST

- La PWA possède une expérience installée claire, premium et mobile-first.
- Le prompt d'installation est discret, beau, contextualisé et non intrusif.
- L'app s'ouvre utilement même en offline.
- L'icône PWA est lisible à petite taille avec identité MAATFEED.
- Le shell app charge vite et restaure le dernier écran.
- Les transitions sont natives-like en mode installé.
- Les contrôles navigateur disparaissent en mode plein écran.
- L'installation reste accessible depuis les paramètres.

## MODE OFFLINE GLOBAL

- Les états connecté, faible connexion, offline partiel et offline complet sont visuellement distincts.
- Le bandeau réseau est discret, informatif et non anxiogène.
- La page offline propose des contenus utiles et pas un écran vide.
- Les actions en attente sont visibles et compréhensibles.
- Le retour réseau déclenche une synchronisation visible.
- Les contenus locaux sont clairement identifiés.
- Les placeholders non disponibles sont explicatifs.

## LOW DATA MODE

- Le Low Data Mode est accessible, compréhensible et réversible.
- Les vidéos ne se lancent jamais automatiquement en connexion faible ou Low Data.
- Le texte et l'audio sont toujours prioritaires sur les médias lourds.
- Le mode économie est visible sans être intrusif.
- Les alternatives légères sont proposées automatiquement.
- Le contrôle utilisateur sur le chargement est total.
- L'esthétique premium est préservée même en mode allégé.

## CACHE INTELLIGENT

- Les contenus téléchargés sont clairement identifiés.
- Le cache temporaire est distingué des sauvegardes volontaires.
- La bibliothèque offline est organisée et navigable.
- La jauge de stockage est informative mais pas stressante.
- Les audios peuvent être téléchargés individuellement ou par série.
- Les débats récemment consultés restent lisibles partiellement offline.
- Les sources/documents sauvegardés restent accessibles localement.

## AUDIO OFFLINE & TÉLÉCHARGEMENTS

- Les audios peuvent être téléchargés, repris, supprimés et joués offline.
- Les séries peuvent avoir un statut de téléchargement global et par épisode.
- La progression d'écoute est sauvegardée localement et synchronisée.
- Le téléchargement peut être mis en attente Wi-Fi.
- Les options qualité sont simples et compréhensibles.
- Le player audio reste stable même en offline.
- Les erreurs de téléchargement proposent des alternatives utiles.

## BROUILLONS & SYNCHRONISATION

- Les brouillons offline sont sauvegardés automatiquement.
- Les réponses texte/audio/vidéo non envoyées ne sont jamais perdues.
- Les actions en attente sont visibles dans une file de synchronisation.
- La publication différée est clairement indiquée.
- Le retour réseau déclenche une synchronisation claire et non bloquante.
- Les erreurs de sync expliquent ce qui est gardé et ce qui doit être corrigé.
- Les médias uploadés sont compressés avant envoi si nécessaire.

## RECHERCHE OFFLINE

- La recherche offline locale ne prétend jamais être une recherche globale.
- Les résultats sont limités aux contenus réellement disponibles.
- L'index local est léger mais utile pour titres, tags et auteurs.
- La saisie est conservée au retour réseau.
- Les filtres par type fonctionnent offline.
- Les brouillons sont inclus dans la recherche locale.
- La recherche reste rapide même sur appareils modestes.

## PERFORMANCE PERÇUE

- Les skeletons reprennent les vraies formes des cartes.
- Les placeholders médias réservent l'espace et évitent les sauts visuels.
- Le texte apparaît avant les médias lourds.
- Les images, vidéos et audios ont des alternatives légères.
- L'autoplay est conditionnel et respecte Low Data.
- Les animations sont réduites sur appareils modestes.
- Le scroll reste fluide même avec chargement progressif.

## OPTIMISATION MÉDIA

- Les formats légers sont utilisés par défaut en réseau faible.
- Les thumbnails sont compressés mais esthétiques.
- Les vidéos proposent une alternative audio.
- Les badges qualité sont humains ("Léger", "Standard", "Haute qualité").
- Le chargement progressif est invisible pour l'utilisateur.
- Les erreurs média proposent des alternatives, pas des impasses.
- La taille des médias est indiquée avant téléchargement.

## ACCESSIBILITÉ & EXPÉRIENCE RÉELLE

- L'application fonctionne correctement sur téléphones modestes.
- Les boutons tactiles respectent les minimums 44px.
- Les contrastes sont forts mais doux.
- Les états réseau sont annoncés textuellement.
- La batterie et le stockage sont respectés.
- L'expérience Afrique est pensée avant le desktop luxe.
- L'application reste digne et accessible même avec data limitée.

## RÈGLES FONDAMENTALES

- MAATFEED reste utile même quand la connexion tombe.
- La performance n'est pas un bonus technique mais une condition d'accès.
- L'utilisateur garde le contrôle total sur sa data et ses médias.
- Aucune création utilisateur n'est perdue par une coupure réseau.
- L'audio est traité comme média prioritaire.
- Le cache automatique ne supprime jamais les téléchargements volontaires.
- L'interface reste premium même en mode allégé.
- L'expérience est pensée pour la réalité mobile africaine.
