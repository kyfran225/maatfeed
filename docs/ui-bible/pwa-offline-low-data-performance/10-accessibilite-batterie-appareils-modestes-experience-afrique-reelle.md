# 10. ACCESSIBILITÉ, BATTERIE, APPAREILS MODESTES & EXPÉRIENCE AFRIQUE RÉELLE

## 1. OBJECTIF UX

MAATFEED doit fonctionner correctement sur des téléphones modestes, avec batterie limitée, stockage restreint, écrans variés et réseau instable. L'expérience doit être premium sans exiger un appareil premium.

## 2. ÉMOTION RECHERCHÉE

L'utilisateur doit ressentir :

- inclusion ;
- confort ;
- dignité ;
- fluidité ;
- respect de son matériel.

L'application ne doit jamais faire sentir à l'utilisateur que son téléphone est "insuffisant".

## 3. STRUCTURE VISUELLE GLOBALE

Le système repose sur :

- motion réduite ;
- médias adaptatifs ;
- cache contrôlé ;
- UI lisible ;
- interactions tactiles larges ;
- options data/batterie ;
- offline clair.

## 4. LAYOUT EXACT

Sur petits écrans :

- pas de colonnes complexes ;
- bottom nav stable ;
- cartes bien espacées ;
- boutons tactiles 44 px minimum ;
- texte jamais trop petit ;
- actions principales accessibles au pouce.

## 5. HIERARCHIE VISUELLE

Priorité :

- lecture/compréhension ;
- action principale ;
- statut réseau ;
- média ;
- décor ;
- animation.

Le décor MAATFEED doit enrichir, jamais ralentir.

## 6. POSITIONNEMENT DES ÉLÉMENTS

Éléments critiques :

- en bas ou centre selon usage pouce ;
- statut réseau sous header ;
- mini-player au-dessus bottom nav ;
- boutons de création accessibles mais non intrusifs.

Sur appareils modestes, éviter les overlays empilés.

## 7. DIMENSIONS & ESPACEMENTS

Minimums :

- bouton tactile : 44 px ;
- marge latérale : 16 px ;
- texte corps : 14 à 16 px ;
- titres carte : 16 à 18 px ;
- bottom nav : 68 à 76 px ;
- mini-player : 56 à 72 px.

## 8. COULEURS

Accessibilité :

- contraste fort mais doux ;
- éviter texte gris trop faible ;
- or utilisé comme accent, pas comme texte long ;
- rouge erreur lisible ;
- vert statut discret mais identifiable.

## 9. TYPOGRAPHIE

Typographie :

- phrases courtes ;
- titres scannables ;
- interlignage confortable ;
- pas de blocs massifs ;
- priorité aux résumés ;
- éviter microtextes critiques.

## 10. BOUTONS

Boutons :

- libellés explicites ;
- pas d'icône seule pour actions critiques ;
- zones larges ;
- états disabled expliqués ;
- feedback immédiat.

## 11. CARTES

Cartes :

- surface sombre ;
- ombre légère ;
- bordure subtile ;
- contenu textuel visible avant média ;
- actions groupées ;
- pas de surcharge.

## 12. ICONOGRAPHIE

Icônes :

- simples ;
- cohérentes ;
- reconnaissables ;
- accompagnées de texte si action critique ;
- taille minimum 18 px.

## 13. COMPORTEMENT SCROLL

Scroll :

- fluide ;
- pas de parallaxe coûteuse ;
- pas d'animations déclenchées en masse ;
- chargement progressif ;
- mémorisation position.

## 14. ANIMATIONS

Animations :

- courtes ;
- réduites si appareil lent ;
- supprimables via préférence ;
- pas de blur lourd partout ;
- pas de glow permanent animé.

## 15. MICRO INTERACTIONS

Micro-interactions :

- press state ;
- check de sauvegarde ;
- retour réseau ;
- téléchargement terminé ;
- brouillon sauvegardé.

Elles doivent rassurer plus qu'amuser.

## 16. GESTURES MOBILE

Gestes :

- simples ;
- standards ;
- tolérantes ;
- sans gestes cachés indispensables ;
- compatibles usage à une main.

## 17. ÉTATS LOADING

Sur appareils modestes :

- skeletons statiques possibles ;
- shimmer limité ;
- médias différés ;
- pas de loader lourd ;
- shell immédiat.

## 18. ÉTATS ERREUR

Erreurs :

- simples ;
- réparables ;
- sans vocabulaire serveur ;
- orientées action.

Exemple :
"Connexion trop faible. Le texte reste disponible, la vidéo attendra."

## 19. ÉTATS OFFLINE

Offline :

- page utile ;
- contenus locaux ;
- actions en attente ;
- audio prioritaire ;
- paramètres cache.

Pas d'écran vide "No Internet" générique.

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

Mobile modeste :

- version la plus importante ;
- design optimisé d'abord ici.

Tablette :

- enrichissement progressif.

Desktop :

- plus de panneaux mais mêmes règles de clarté.

## 21. ACCESSIBILITÉ

Respecter :

- contraste ;
- labels ;
- tailles tactiles ;
- réduction mouvement ;
- navigation clavier ;
- alt media ;
- captions/transcriptions ;
- textes compréhensibles.

## 22. PERFORMANCE UX

Optimiser :

- première ouverture ;
- retour app ;
- scroll feed ;
- audio ;
- cache ;
- taille média ;
- interactions.

L'app doit rester réactive même si les données arrivent lentement.

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

Règle d'or : MAATFEED doit fonctionner dans la vraie vie, pas seulement dans un bureau avec fibre.
Cela implique :

- pas d'autoplay agressif ;
- audio offline ;
- contenus texte utiles ;
- compression ;
- reprise sync ;
- PWA légère ;
- installation sans store.

## 24. RÈGLES NON NÉGOCIABLES

- Ne jamais exiger un téléphone puissant pour une expérience correcte.
- Ne jamais rendre les vidéos indispensables.
- Ne jamais sacrifier la lisibilité au décor.
- Ne jamais perdre une action utilisateur.
- Toujours respecter data, batterie et stockage.
- Toujours offrir une voie légère.
- Toujours penser mobile Afrique avant desktop luxe.
