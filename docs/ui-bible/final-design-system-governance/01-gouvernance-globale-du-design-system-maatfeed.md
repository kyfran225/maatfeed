# 1. GOUVERNANCE GLOBALE DU DESIGN SYSTEM MAATFEED

## 1. OBJECTIF UX

La gouvernance du design system doit empêcher la dérive visuelle, fonctionnelle et émotionnelle de MAATFEED.
Chaque nouvelle page, modale, carte, interaction ou composant doit respecter :

- l'identité noir/or ;
- la profondeur premium ;
- la logique mobile-first ;
- la priorité audio/débat/savoir ;
- la faible connexion Afrique ;
- la clarté cognitive ;
- la cohérence des gestes ;
- la continuité offline ;
- la sobriété élégante.

L'objectif est que l'utilisateur reconnaisse MAATFEED en une seconde, même sans logo.

## 2. ÉMOTION RECHERCHÉE

L'ensemble de l'interface doit produire une sensation de :

- profondeur ;
- intelligence ;
- confiance ;
- calme ;
- puissance culturelle ;
- modernité africaine ;
- maîtrise ;
- fluidité.

MAATFEED ne doit jamais paraître bricolée, froide, criarde ou copiée. L'app doit avoir une présence : sombre, noble, vivante, presque nocturne, avec l'or comme fil d'Ariane.

## 3. STRUCTURE VISUELLE GLOBALE

Toute interface MAATFEED doit respecter une architecture en couches :

- fond profond : noir charbon, jamais blanc par défaut ;
- surfaces élevées : cartes, sheets, modales, panels ;
- accents culturels : or/ambre, motifs subtils, symboles non envahissants ;
- contenu : texte, audio, vidéo, débat, série, document ;
- actions : boutons, réactions, menus, création ;
- statuts : offline, sync, premium, sécurité, IA, data ;
- motion : transitions discrètes et cohérentes.

Chaque couche doit être lisible, séparée et harmonisée.

## 4. LAYOUT EXACT

Règles globales :

- mobile d'abord ;
- marges latérales mobiles entre 16 et 20 px ;
- cartes avec radius généreux ;
- bottom nav stable ;
- mini-player audio toujours au-dessus de la bottom nav ;
- safe areas respectées ;
- aucun contenu important collé aux bords ;
- desktop enrichi par panels, jamais par densité excessive.

La grille doit toujours privilégier la respiration. MAATFEED n'est pas un tableau de bord. C'est un espace immersif de savoir.

## 5. HIERARCHIE VISUELLE

Hiérarchie globale :

- contenu principal ;
- contexte culturel ou éditorial ;
- action principale ;
- signaux de confiance ;
- actions sociales ;
- recommandations ;
- métadonnées ;
- options secondaires.

Les badges, sponsors, boutons secondaires et menus ne doivent jamais voler la scène au contenu.

## 6. POSITIONNEMENT DES ÉLÉMENTS

Règles de positionnement :

- les actions principales doivent être accessibles au pouce sur mobile ;
- les éléments de statut doivent rester proches de l'objet concerné ;
- les boutons destructifs doivent être isolés ;
- les menus secondaires doivent rester discrets ;
- le player audio doit garder une place persistante ;
- les prompts doivent apparaître en contexte, jamais comme intrusion.

Tout élément flottant doit avoir une raison. Pas de bouton décoratif perdu dans l'espace.

## 7. DIMENSIONS & ESPACEMENTS

Règles dimensionnelles :

- zone tactile minimale : 44 px ;
- hauteur lignes réglages : 56 à 68 px ;
- cartes feed : généreuses, jamais écrasées ;
- boutons principaux : 48 à 54 px de haut ;
- capsules : 28 à 36 px ;
- bottom sheets : radius 24 à 32 px ;
- modales : padding 20 à 24 px mobile ;
- espaces entre sections : 20 à 28 px.

La densité doit être contrôlée. MAATFEED peut être riche, mais jamais étouffante.

## 8. COULEURS

Palette finale obligatoire :

- fond principal : noir charbon profond ;
- fond secondaire : brun noir premium ;
- surface carte : noir chaud légèrement élevé ;
- surface modale : noir brun plus dense ;
- texte principal : ivoire doux ;
- texte secondaire : beige-gris ;
- texte tertiaire : gris chaud ;
- accent principal : ambre/or ;
- accent premium : or profond ;
- succès : vert discret ;
- erreur : rouge argile ;
- avertissement : ambre sombre ;
- offline : brun/or doux ;
- IA : aura symbolique subtile, jamais bleu robot générique.

Interdits :

- blanc pur dominant ;
- bleu SaaS générique ;
- gris dashboard froid ;
- vert fluo ;
- rouge agressif ;
- gradients arc-en-ciel ;
- couleurs sans lien avec l'univers MAATFEED.

## 9. TYPOGRAPHIE

La typographie doit être :

- moderne ;
- lisible ;
- noble ;
- sobre ;
- adaptée mobile.

Règles :

- titres forts mais pas énormes ;
- corps de texte 14 à 16 px minimum ;
- interlignage confortable ;
- métadonnées lisibles ;
- microtexte jamais critique ;
- pas de paragraphes massifs sans respiration.

Le ton écrit doit rester humain, direct, intelligent et culturellement sensible.

## 10. BOUTONS

Familles de boutons :

- principal : ambre/or, texte sombre ;
- secondaire : surface sombre bordée ;
- tertiaire : texte seul ;
- danger : rouge argile sobre ;
- média : play/pause clair ;
- offline : statut + action ;
- premium : or profond mais non tape-à-l'œil.

Règle : un écran ne doit jamais présenter trois boutons principaux concurrents.

## 11. CARTES

Toutes les cartes MAATFEED doivent avoir :

- fond sombre élevé ;
- radius premium ;
- bordure subtile ;
- ombre douce ;
- hiérarchie texte claire ;
- action principale identifiable ;
- états loading/offline/erreur prévus.

Types de cartes à harmoniser :

- carte vidéo ;
- carte audio ;
- carte débat ;
- carte article/document ;
- carte série ;
- carte créateur ;
- carte notification ;
- carte premium ;
- carte offline ;
- carte brouillon ;
- carte IA ;
- carte source.

## 12. ICONOGRAPHIE

L'iconographie doit être :

- fine ;
- arrondie ;
- symbolique ;
- cohérente ;
- non enfantine ;
- non corporate générique.

Icônes clés :

- audio : casque, onde ;
- débat : bulles, branches ;
- savoir : document, source ;
- IA : symbole abstrait non humain ;
- offline : nuage barré, check local ;
- sécurité : bouclier ;
- premium : étoile/or ;
- culture : symboles abstraits subtils.

Aucune icône ne doit remplacer une explication sur les actions critiques.

## 13. COMPORTEMENT SCROLL

Le scroll MAATFEED doit être :

- fluide ;
- stable ;
- sans sauts de layout ;
- sans autoplay agressif ;
- sans surcharge d'animations ;
- capable de mémoriser la position ;
- adapté aux longues sessions.

Règles :

- feed : continuité ;
- débat : retour au bon niveau de réponse ;
- audio : player persistant ;
- recherche : conserver la requête ;
- paramètres : restaurer la position ;
- offline : fin de liste claire.

## 14. ANIMATIONS

La motion MAATFEED doit être lente juste ce qu'il faut, sombre, élégante, jamais gadget.
Principes :

- transitions courtes ;
- fondu doux ;
- montée de bottom sheet naturelle ;
- micro-halo or très rare ;
- press states tactiles ;
- shimmer skeleton discret ;
- réduction motion respectée.

Interdits :

- rebonds cartoon ;
- animations permanentes inutiles ;
- parallaxes coûteuses ;
- effets de fête ;
- motion qui ralentit l'accès au contenu.

## 15. MICRO INTERACTIONS

Micro-interactions obligatoires :

- sauvegarde confirmée ;
- brouillon protégé ;
- audio repris ;
- action offline en attente ;
- retour réseau ;
- téléchargement terminé ;
- réaction ajoutée ;
- réponse publiée ;
- option modifiée ;
- erreur réparée.

Chaque micro-interaction doit répondre à une inquiétude utilisateur : "est-ce que ça a marché ?"

## 16. GESTURES MOBILE

Gestures autorisées :

- swipe back ;
- swipe down sheet/player ;
- pull-to-refresh intelligent ;
- long press options média ;
- swipe action uniquement pour options non destructives ;
- tap clair pour actions principales.

Gestures interdits :

- suppression critique par simple swipe ;
- interaction cachée indispensable ;
- double tap obligatoire pour comprendre ;
- geste qui entre en conflit avec scroll feed ;
- geste qui bloque le player audio.

## 17. ÉTATS LOADING

Chaque composant doit avoir un état loading adapté :

- feed : skeleton cartes ;
- audio : waveform fantôme ;
- débat : thread skeleton ;
- profil : header skeleton ;
- paramètres : lignes skeleton ;
- recherche : résultats skeleton ;
- offline : contenu local immédiat ;
- paiement : étape claire ;
- IA : attente contextualisée.

Interdit : spinner plein écran utilisé comme solution universelle.

## 18. ÉTATS ERREUR

Les erreurs doivent être :

- humaines ;
- courtes ;
- proches du contexte ;
- réparables ;
- visuellement cohérentes ;
- jamais techniques en premier niveau.

Exemples d'esprit :

- "Connexion trop faible. Le texte reste disponible."
- "Cette vidéo ne charge pas. Tu peux écouter l'audio."
- "Ta réponse est gardée en brouillon."
- "Le paiement n'a pas abouti. Aucun accès n'a été débité."

## 19. ÉTATS OFFLINE

Toute page importante doit prévoir :

- offline complet ;
- offline partiel ;
- contenu local ;
- action en attente ;
- retour réseau ;
- message clair ;
- alternative légère.

MAATFEED ne doit jamais afficher une page morte "No Internet" sans valeur.

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

Priorité absolue :

- mobile ;
- mobile faible connexion ;
- mobile installé PWA ;
- tablette ;
- desktop.

Desktop ne doit pas changer l'âme de l'app. Il peut enrichir :

- panels ;
- colonnes ;
- workspace débat ;
- bibliothèque plus large ;
- player sticky ;
- recherche avancée.

Mais il ne doit jamais transformer MAATFEED en back-office.

## 21. ACCESSIBILITÉ

Chaque écran doit respecter :

- contraste lisible ;
- taille tactile ;
- labels ;
- navigation clavier desktop ;
- lecteur d'écran ;
- réduction motion ;
- captions vidéo si disponibles ;
- transcriptions audio si disponibles ;
- textes d'erreur explicites ;
- états non dépendants de la couleur seule.

L'accessibilité n'est pas un add-on. C'est une preuve de maturité.

## 22. PERFORMANCE UX

Principes finaux :

- shell rapide ;
- texte avant média ;
- audio avant vidéo ;
- lazy loading intelligent ;
- cache utile ;
- skeletons courts ;
- pas de requêtes inutiles ;
- pas de media autoplay coûteux ;
- offline-first sur contenus critiques.

La performance perçue compte autant que la performance mesurée.

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

Toutes les décisions UI doivent passer le test suivant :
"Est-ce que cela reste utilisable avec une connexion instable, un téléphone modeste et une data chère ?"
Si la réponse est non, la solution n'est pas MAATFEED-ready.

Obligatoire :

- mode économie visible ;
- audio léger ;
- vidéos manuelles ;
- cache ;
- téléchargements ;
- brouillons offline ;
- sync différée ;
- messages simples ;
- pas de honte utilisateur.

## 24. RÈGLES NON NÉGOCIABLES

- Ne jamais produire une UI générique.
- Ne jamais casser l'identité noir/or.
- Ne jamais copier TikTok directement.
- Ne jamais transformer MAATFEED en dashboard SaaS.
- Ne jamais rendre la vidéo indispensable.
- Ne jamais négliger l'audio.
- Ne jamais perdre une action utilisateur.
- Ne jamais ignorer faible connexion Afrique.
- Ne jamais cacher les paramètres critiques.
- Ne jamais sacrifier lisibilité pour décor.
- Ne jamais afficher une erreur technique brute.
- Toujours préserver le premium calme.
- Toujours protéger la continuité utilisateur.
