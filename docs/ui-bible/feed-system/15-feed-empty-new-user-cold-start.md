# 15. FEED EMPTY, NEW USER & COLD START

## 1. OBJECTIF UX

Donner une expérience forte dès la première ouverture, même avant que l'utilisateur ait beaucoup d'historique.

## 2. ÉMOTION RECHERCHÉE

Bienvenue, curiosité, simplicité. Le nouvel utilisateur ne doit pas se sentir devant un vide.

## 3. STRUCTURE VISUELLE GLOBALE

Feed initial mélange contenus éditoriaux forts, débats du jour, audios populaires, séries de départ, créateurs recommandés.

## 4. LAYOUT EXACT

Première carte : contenu hero ou débat du jour. Ensuite : module intérêts rapides, contenu audio, série, vidéo, créateurs à suivre.

## 5. HIERARCHIE VISUELLE

Contenu hero d'abord. Choix d'intérêt ensuite seulement si léger. Pas de formulaire lourd avant consommation.

## 6. POSITIONNEMENT DES ÉLÉMENTS

Module "Choisissez vos intérêts" peut apparaître après 2 ou 3 contenus, pas forcément en premier. Il doit être skippable.

## 7. DIMENSIONS & ESPACEMENTS

Module intérêts : carte 160-240 px, chips 32-36 px, CTA 44 px.

## 8. COULEURS

Module onboarding dans feed : surface sombre, bordure or faible, CTA doré.

## 9. TYPOGRAPHIE

Titre module : 17-19 px. Description courte : 13-14 px. Chips : 12-13 px.

## 10. BOUTONS

"Personnaliser", "Plus tard", chips thèmes. Ne pas obliger l'utilisateur.

## 11. CARTES

Les cartes cold start doivent être éditorialement fortes et variées : une vidéo, un audio, un débat, une série.

## 12. ICONOGRAPHIE

Icônes thèmes : histoire, spiritualité, débat, musique, culture, science. Sobres.

## 13. COMPORTEMENT SCROLL

Le nouvel utilisateur peut scroller immédiatement. L'onboarding ne bloque pas le feed.

## 14. ANIMATIONS

Module intérêts apparaît comme carte normale. Sélection chip : feedback doré.

## 15. MICRO INTERACTIONS

Tap chip : sélection instantanée. CTA personnaliser : transition douce vers préférences.

## 16. GESTURES MOBILE

Aucun geste caché. Skipper visible.

## 17. ÉTATS LOADING

Si contenus initialement chargent lentement, afficher skeleton + message "Préparation de votre feed".

## 18. ÉTATS ERREUR

Si cold start échoue : afficher contenus cache/app éditoriaux intégrés si disponibles. Sinon état erreur utile.

## 19. ÉTATS OFFLINE

Première ouverture offline : afficher page explicative légère + possibilité réessayer. Si déjà ouvert, contenus cache.

## 20. RESPONSIVE MOBILE/TABLET/DESKTOP

Desktop : module intérêts peut être dans panneau droit. Mobile : dans feed.

## 21. ACCESSIBILITÉ

Chips sélectionnables annoncées. Skipper accessible.

## 22. PERFORMANCE UX

Ne pas attendre personnalisation complète. Afficher contenu éditorial rapidement.

## 23. COMPORTEMENT FAIBLE CONNEXION AFRIQUE

Cold start doit utiliser contenus légers : audio, texte, miniatures compressées, débats texte.

## 24. RÈGLES NON NÉGOCIABLES

Pas de mur d'onboarding obligatoire. Pas de feed vide. Pas de formulaire interminable avant de voir la valeur.
